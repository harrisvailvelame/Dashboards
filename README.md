## Repository conventions

- one directory per analytical product;
- each project has its own `README.md`;
- artifact names use stable, descriptive English identifiers;
- binary reports are preserved as `.pbix` and reviewable static exports;
- no client or employer proprietary data is published;
- historical projects are documented as historical work rather than presented as production systems.

## Analytical approach

- Define the business grain before visualization.
- Separate raw fields from business metrics.
- Prefer a small set of decision-oriented KPIs.
- Keep filters and dimensions consistent across views.
- Use visual hierarchy to emphasize exceptions and trends.
- Treat dashboards as the serving layer of a broader data pipeline.
